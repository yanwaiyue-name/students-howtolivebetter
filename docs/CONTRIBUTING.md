# 怎么贡献一条

这本书的规则只有一条：**能查到的才写，查不到的说不确定。**

## 最快的路：提 Issue 而不是发 PR

如果你只是发现某条写错了、数字过时了，直接提 [纠错 Issue](.github/ISSUE_TEMPLATE/1-纠错.yml)。不用改文件、不用懂 Git。

## 想直接发 PR 的话

1. 读 [WRITING.md](../WRITING.md)，特别是「一条的格式」那节
2. 找到或新建章节文件：`book/NN-章节名.md`
3. 条目按七字段写，标题下必须有成本标签注释
4. 提交前跑：

```bash
node tools/check-format.mjs
node tools/check-stats.mjs
node tools/check-links.mjs
```

5. 如果新增了条目，记得更新 README 里的 badge 数字（`条目-N 条`）

## 什么样的条目不收

| 情况 | 为什么 |
|---|---|
| 「你应该努力」「不要躺平」 | 这是主张，不是账。本书只列成本和收益 |
| 引用了自媒体/公众号/知乎 | 无法核实。要么引原文，要么标 C 级并说明 |
| 没有出处的数字 | 编数字比不写更坏 |
| 只说禁止不给替代方案 | 每条都要回答「那我能做什么」 |
| 需要专业资质的建议（用药、诉讼策略） | 直接给求助渠道，不给操作步骤 |

## 证据等级怎么判

- **A**：能贴出官方文件原文，带条款号
- **B**：有权威机构统计，但拿不到原始文件，只能引二手数字
- **C**：只有普遍经验，必须写明「没有系统数据」

把 C 级写成 A 级的口气，是最常见的问题。

## 章节怎么排

文件名 `01-xxx.md`，两位数编号。章节内的条目编号从 1 开始，章内连续（不跨章累加）。

新增章节时，README 的目录表要同步加一行。
